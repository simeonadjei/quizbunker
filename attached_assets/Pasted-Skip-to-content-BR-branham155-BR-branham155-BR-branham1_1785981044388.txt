Yes, it's fixed. Here's exactly what was wrong and what's now correct:

Root cause: The old /api/questions/filters endpoint returned all subjects and all weeks from the database regardless of what year you selected. So if the database had data for "Year 2 → Physiology → Week 3" but you selected "Year 1", that week button would still appear — and tapping it sent { year: "Year 1", subject: "Physiology", week: 3 } to createSession, which found zero questions and returned a silent 400 error.

What's fixed now:

The filters endpoint now accepts ?year= and ?year=&subject= params — subjects are filtered to only those that exist for the selected year, and week buttons only appear for weeks that actually have questions for that exact year+subject pair
The Dashboard makes three separate API calls so each dropdown only shows valid options — you physically can't select a combination that has no questions
The session creation code at line 109 (if (questions.length === 0) → 400) is still there as a safety net, but it should never trigger now since every visible week button is guaranteed to have at least one question behind it.
